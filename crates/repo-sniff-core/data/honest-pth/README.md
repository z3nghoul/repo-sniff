# Known honest `.pth` lines

`.pth` files that Python really executes at start-up and that legitimate
tools install. The scanner treats a `.pth` file as an honest form only when
**both the file name and every effective line** match one of these, and lowers
the severity accordingly. They are stored as text files and embedded in the
binary; each line is compared after trimming surrounding whitespace.

All of them were taken from the sources of the tools, not written from
memory.

| File | Name it is used with | Source |
|---|---|---|
| `setuptools-distutils-precedence.txt` | `distutils-precedence.pth` | `_pth_contents` in `setup.py` of pypa/setuptools, rendered the way setuptools renders it (`\n` becomes `; `). One line per variant found in release tags: V1 `v49.3.0` to `v49.6.0`, V2 `v50.0.0` and `v60.0.0` onwards (the current text, also verified against setuptools 84.2.1 on a real system), V3 `v50.3.2` to `v59.8.0` (default `'stdlib'`), V4 `v60.1.0` only (`ensure_shim`). Tags between the sampled ones were not all inspected. |
| `pytest-cov.txt` | `pytest-cov.pth` | `src/pytest-cov.pth` of pytest-dev/pytest-cov, identical from `v2.12.1` to `v6.2.1`. pytest-cov 7.0.0 and later no longer ship the file (CHANGELOG 7.0.0). The first versions have no final newline, the later ones do; the comparison ignores it. |

Forms that are generated by code instead of listed here:

- `_virtualenv.pth` containing `import _virtualenv`
  (`src/virtualenv/create/via_global_ref/api.py` of pypa/virtualenv; only
  written for Python older than 3.10).
- `__editable__.<name>.pth` containing
  `import __editable___X_finder; __editable___X_finder.install()` with the
  same `X` twice (verified with a real editable install).
- `<name>-nspkg.pth` for legacy namespace packages, generated from the
  template in `setuptools/namespaces.py` (two texts: with `has_mfs`, setuptools
  `v38.0.0` to `v68.0.0`, and without, `v70.0.0` onwards; older releases were
  not inspected).
